# Releases

GitHub Releases is the distribution channel. Use Semantic Versioning and tags such as `v0.1.0`. Name the release with the version and the qualified feature milestone.

The first release is **0.1.0 · Connection and execution**. The release draft tracks the intended scope while the milestone is in development.

Before publication, build the server distribution and Blender extension archive from a tagged commit. Test installation and startup from those exact archives. Attach the distributions, `SHA256SUMS`, and a qualification note with the Blender versions, operating systems, live and background tests, and known limitations. Record the release in the [changelog](../CHANGELOG.md) and close the milestone once its acceptance evidence is complete.
